# Первый тест своего сервера в SoulFire: вход → капча → регистрация

## Короткий ответ

**Да, для ваших трёх условий SoulFire — лучший вариант.** Но с одной честной оговоркой:

- **Капча** — только SoulFire её умеет решать из коробки (полный клиент + AI-плагин). Заливные
  инструменты (mc-bots, rust-mc-bot, BotMark) не могут в принципе: их бот не видит мир.
- **Управление ботами** — только у SoulFire есть GUI + команды + скрипты + SDK.
- **Стресс-тест** — SoulFire лучший по *качеству* измерений (настоящий клиентский код), но не по
  *количеству* ботов на одно железо. Потолок входа добирается заливным инструментом отдельным окном.

То есть: **SoulFire = ядро** (вход, капча, регистрация, поведение, отчётность), а
**mc-bots/rust-mc-bot = добить числом** на этапе поиска предела. Для первого теста вам нужен
только SoulFire.

## Шаг −1. Что скачать и установить (это и есть «локально»)

**Да, для первого теста всё работает локально на вашем ПК.** Десктопное приложение
**SoulFireClient** содержит внутри себя **Integrated server (local)** — то есть backend SoulFire
запускается прямо в приложении. Отдельная Java, Docker, VPS и JAR-файлы **не нужны**.

Куда идти: **https://soulfiremc.com/download** (страница сама подставит вашу ОС) или напрямую
релизы клиента: https://github.com/soulfiremc-com/SoulFireClient/releases

Что именно качать под свою систему (версия клиента на момент проверки — 2.10.1):

| Система | Файл |
|---|---|
| Windows, Intel/AMD (x64) | `SoulFire-2.10.1-x64.exe` (~169 МБ) |
| Windows, ARM (Snapdragon-ноутбуки) | `SoulFire-2.10.1-arm64.exe` |
| macOS, Apple Silicon (M-серия) | `SoulFire-2.10.1-arm64.dmg` |
| macOS, Intel | `SoulFire-2.10.1-x64.dmg` |
| Linux, Debian/Ubuntu (x86_64) | `SoulFire-2.10.1-amd64.deb` или `SoulFire-2.10.1-x86_64.AppImage` |
| Linux, Fedora/RHEL | `SoulFire-2.10.1-x86_64.rpm` |
| Linux, Arch | `SoulFire-2.10.1-x64.pacman` |

Требования: Windows 10+ / современный macOS / почти любой Linux; большой размер (~130–220 МБ)
нормален — внутрь упакованы клиент Minecraft и headless-Vulkan-рантайм (системный Vulkan, GPU и
дисплей не требуются).

**НЕ нужно для первого теста** (это для следующего этапа, «когда захочется автоматизации или
выделенной машины»): `SoulFireCLI-*.jar` и `SoulFireDedicated-*.jar` с
https://github.com/soulfiremc-com/SoulFire/releases.

Скачивайте только с `soulfiremc.com` и официальных GitHub-релизов; на Windows сборка подписана.

### Что значит «локально» и в чём подвох

- Backend = ваш ПК. Значит **адрес Minecraft-сервера резолвится и подключается с вашего ПК**:
  - сервер на том же ПК → `127.0.0.1:25565`;
  - сервер на хостинге → его публичный адрес, соединение пойдёт через ваш интернет.
- Сервер увидит **ваш домашний IP**. Поэтому если у вас есть anti-bot/лимиты по IP — в вайтлист
  нужно добавить именно ваш домашний IP (для локального теста этого обычно достаточно).
- Ваш ПК должен оставаться включённым с открытым приложением на время прогона: закрыли приложение
  или пропал интернет — боты отваливаются. (Состояние «какие боты должны работать» сохраняется и
  восстанавливается при следующем старте, но соединение живёт только пока работает backend.)
- Канал: на 1–10 ботов домашнего интернета хватает; для десятков ботов и «потолка соединений»
  лучше вынести backend на отдельную машину/VPS (Dedicated server) — но это уже второй этап.
- Если Minecraft-сервер крутится **на том же ПК**, что и SoulFire, они конкурируют за CPU/RAM:
  для честных цифр на ступенях 20+ ботов разносите их по разным машинам.

## Экран «Подключение к серверу SoulFire» (первый запуск приложения)

Что здесь ставить:

| Поле | Что делать |
|---|---|
| **Start automatically next time** | Можно включить — тогда при следующем запуске этот экран пропускается и SoulFire сразу стартует. Ошибки не будет ни в каком положении; включайте, когда убедитесь, что всё работает |
| **JVM аргументы** | **Единственное место, которое стоит поправить.** По умолчанию SoulFire берёт 25% доступной памяти — для нескольких ботов этого может не хватить. Допишите в конец строки ` -Xmx8G` (через пробел), подобрав по таблице ниже. Остальные аргументы (`-XX:+EnableDynamicAgentLoading -XX:+UnlockExperimentalVMOptions`) не трогайте, а кнопка ↺ вернёт значения по умолчанию |
| **Server jar** | Оставить **Official** — приложение скачает и проверит подходящий релиз сервера SoulFire. **Custom** нужен только для своей сборки/dev-jar |
| Кнопки «Открыть каталог данных», «Диагностика процессов» | Понадобятся позже: там лежат конфиги, логи и папка `minecraft/mods` для community-плагинов |
| **Запуск** | Нажать. Первый запуск = скачивание серверной части, это нормально |

**Сколько памяти выделять (`-Xmx`)** — боты это полноценные Minecraft-клиенты, память им нужна:

| ОЗУ на ПК | Рекомендуется | Комментарий |
|---|---|---|
| 4 ГБ | оставить по умолчанию (25%) | 1–3 бота |
| 8 ГБ | `-Xmx3G` | оставьте 2+ ГБ системе |
| 16 ГБ | `-Xmx8G` | комфортно для ~10–20 ботов |
| 32 ГБ | `-Xmx16G` | для десятков ботов |

Правила:
- **Никогда не ставьте `-Xmx` близко к объёму всей ОЗУ** — оставляйте 2–4 ГБ системе, иначе ПК начнёт свопить.
- Если Minecraft-сервер крутится **на этом же ПК**, вычтите его аллокацию: 16 ГБ ОЗУ, серверу 4 ГБ → ботам `-Xmx8G`, не больше.
- Итог слишком мал → в логах `OutOfMemoryError: Java heap space`, боты отваливаются. Слишком велик → тормозит вся система.
- Опционально для больших флотов: добавить `-XX:+UseZGC` (меньше пауз GC), но для 1–10 ботов это не нужно.

## Что понадобится

| Что | Детали | Обязательно? |
|---|---|---|
| **SoulFireClient (desktop)** | Windows / macOS / Linux. Запускаете «Integrated server (local)» — отдельный Java не нужен | **Да** |
| Ваш Minecraft-сервер | Желательно **копия** на другом порту, с бэкапом мира и конфигов | **Да** |
| **Тестовые аккаунты** | Offline (если сервер в offline-mode) — генерируются прямо в GUI. Для online-mode — Microsoft-аккаунт (credentials / device code) | **Да** |
| **AI-провайдер** | Ключ OpenAI **или** Groq (`https://api.groq.com/openai/v1`), **или** локальная Ollama (тогда `llava` — капча не уходит в облако) | **Да, если капча картинкой** |
| Понимание типа капчи | Карта в руке / капча на экране / код текстом в чате — от этого зависит режим плагина | Да |
| Прокси | На первом тесте **не нужны** | Нет |
| Spark на сервере | Для метрик MSPT/TPS | Очень желательно |

## Шаг за шагом (GUI)

### Шаг 0. Подготовьте сервер (10 минут)

```
1. Копия сервера на другом порту (server-port=25566), бэкап мира.
2. Отключите на тестовой копии то, что мешает измерению конкретно этого теста:
   лимиты по IP, агрессивные рейт-лимиты. НО капчу НЕ отключайте — мы её и проверяем.
3. bukkit.yml:  connection-throttle: 0     # иначе Bukkit режет входы: 1 за 4000 мс
4. server.properties:
   online-mode=false        # если боты оффлайн; иначе — импортируйте Microsoft-аккаунт
   max-players=200
   allow-flight=true        # если планируете летающих ботов/подъёмы
5. Spark: /spark tps  →  зафиксируйте baseline (MSPT должен быть < 10 мс на пустом сервере)
```

Держите **обычный игрок-клиент** подключённым: удобно видеть чат ботов и проверять капчу глазами.

### Шаг 1. Запустите SoulFire и создайте инстанс

1. Откройте SoulFireClient → выберите **Integrated server (local)** (не Demo — демо не подключает
   реальных ботов).
2. **Instances** → **Create Instance** → имя, например `Test1` → открыть.
3. Инстанс — это изолированная песочница: свои аккаунты, прокси, плагины, настройки.

### Шаг 2. Bot Settings — цель и режим входа

| Настройка | Что поставить на первый тест |
|---|---|
| Server address | адрес вашего тестового сервера (для локального — `127.0.0.1:25566`) |
| Protocol version | версия, **совпадающая с вашим сервером** (для старых версий перевод делает ViaFabricPlus) |
| Join delay | оставить по умолчанию **1000–3000 мс** — плавный вход, не «залп» |
| Concurrent connects | оставить `1` на первый раз (по одному подключению за раз) |
| Render distance (client settings) | по умолчанию **2** — для теста загрузки чанков поднимите позже осознанно |
| Proxies | **не подключать** на первый тест |
| Автоматизацию (kill-aura, auto-chat и пр.) | **выключить** — сначала чистый вход |

### Шаг 3. Аккаунты

**Если сервер в offline-mode (проще всего для первого теста):**
Account Settings → диалог генерации offline-аккаунтов → задайте:
- amount: `1` (сначала ровно один!)
- name format: `TestBot_%d` → получится `TestBot_1`
- проверьте режим обработки дубликатов, затем посмотрите список аккаунтов.

**Если сервер в online-mode:** Account Settings → тип **Microsoft Java Device Code**
(значительно безопаснее, чем хранить пароль) → пройдите вход в браузере.

> Offline-ники **чувствительны к регистру**, а AuthMe может отклонять имена, отличающиеся только
> регистром. Ники должны быть уникальными: дубликат = кик предыдущего бота.

### Шаг 4. Плагины — сердце этого теста

Откройте **Plugins**, включите нужное, затем в **Plugin Settings** настройте:

| Плагин | Включать? | Зачем и что настроить |
|---|---|---|
| **`auto-register`** | **Да, если сервер с AuthMe** | Ловит в чате `/register`, `/reg`, `/login`, `/l` и отправляет шаблон. По умолчанию: `/register %password% %password%` и `/login %password%`, пароль по умолчанию `SoulFire`, задержка 0–1000 мс. **Поставьте отдельный тестовый пароль**, а не свой реальный |
| **`captcha-solver`** | **Да, если есть капча** | См. Шаг 5 |
| `chat-logger` | Уже включён | Показывает чат ботов в терминале — так вы увидите и капчу, и запросы регистрации |
| `disconnect-logger` | Уже включён | Сразу видно причину кика (капча не решена, дубликат ника, бан и т.п.) |
| `client-settings` | Уже включён | Отправляет корректные настройки клиента — важно для анти-ботов, проверяющих settings-пакет |
| `auto-reconnect` | По ситуации | Включён по умолчанию. На тесте **входа** держите **выключенным**: иначе искажаются «сколько ботов отвалилось». Включите позже, на этапе проверки восстановления |
| `server-list-bypass` | Только если анти-бот требует пинг | Пингует список серверов перед входом (обход проверок вида EpicGuard). На чистом тесте не нужен |
| `forwarding-bypass` | Только за прокси-сетью | `LEGACY` / `BUNGEE_GUARD` / `MODERN` (Velocity) / `SF_BYPASS` (+ плагин SoulFireBypass на прокси). Для обычного standalone-сервера — **выключено** |
| `anti-afk`, `auto-chat-message`, `kill-aura` | Позже | Это уже поведенческая нагрузка, не первый вход |

### Шаг 5. AI Settings + настройка капчи

**AI Settings (общий провайдер):**

| Поле | Значение |
|---|---|
| API Base URL | OpenAI — по умолчанию `https://api.openai.com/v1`; Groq — `https://api.groq.com/openai/v1`; Ollama — адрес вашего сервера |
| API Key | ключ провайдера (для локальной Ollama может быть пустым) |
| Request timeout / Max retries | по умолчанию 60 с и 5 попыток — оставьте |

Провайдер должен быть **доступен с машины, где работает SoulFire backend** (в Docker — учитывайте сеть
контейнера).

**Plugin Settings → Captcha Solver:** выберите режим строго по своей капче.

| Ваша капча | Режим (`Image Source` / `Captcha Trigger`) | Обязательные настройки |
|---|---|---|
| **Карта в руке** (mapcha, Minecaptcha, CaptchaVerifyZ) | `MAP_IN_HAND` (+ `CHAT_MESSAGE`) | **Model: vision-модель** (локально `llava`, Groq `meta-llama/llama-4-scout-17b-16e-instruct`), Prompt, Response Command |
| **Капча на экране/в мире** | `POV_RENDER` (+ `CHAT_MESSAGE`) | то же + **POV Render Width/Height** поднять (по умолчанию 854×480), пока цифры не станут читаемыми |
| **Код уже в чате текстом** | `TEXT_BASED` | **Captcha Regex** с группой захвата (по умолчанию `/captcha (\w+)`) + Response Command. Модель не нужна |
| Картинка после сообщения в чате | `CHAT_MESSAGE` | **Text Trigger** (по умолчанию `/captcha`) |

Значения по умолчанию (чтобы понимать, что менять): модель `llava`, `Image Source = MAP_IN_HAND`,
`Captcha Trigger = CHAT_MESSAGE`, text trigger `/captcha`, regex `/captcha (\w+)`,
Response Command `%s` (без `/` — просто чат-сообщение), POV 854×480.

**Два подводных камня, которые ломают капчу чаще всего:**

1. **`MAP_IN_HAND` читает карту из главной руки** — то есть из *выбранного* слота хотбара.
   Если капча-плагин выдаёт карту в другой слот (например, mapcha по умолчанию даёт её в слот `4`),
   бот может «не видеть» карту. Проверяется за секунды: `inventory current` (что у бота в руках) и
   `export-map` / `export-map <map_id>` — **экспортируйте карту и посмотрите на неё глазами**, прежде
   чем винить модель. Если карта не в руке — поменяйте `inventory_slot` в конфиге капчи или выберите
   другой источник (`POV_RENDER`).
2. **Ответ обрезается до 32 символов** (лимит генерации 64 токена). Для длинных кодов не подойдёт.

> Капча-плагины, которые вам встретятся: **mapcha** (permission `mapcha.bypass` для тестовой
> машины), **Minecaptcha**, **CaptchaVerifyZ**, чат-верификация у **UltimateAntiBot** (код в чате →
> режим `TEXT_BASED`).

### Шаг 6. Первый бот — «сухой прогон»

1. **Overview** → запустите **ровно одного** бота (`TestBot_1`).
2. Смотрите одновременно: **Terminal** в SoulFire, консоль Minecraft-сервера и ваш обычный клиент.
3. Ожидаемая последовательность:

```
[бот вошёл]                     → сервер пишет "TestBot_1 joined the game"
/captcha (или карта в руке)     → видно в chat-logger
[бот решает капчу]              → в терминале SoulFire видно отправленный ответ
[запрос /register]              → auto-register ловит /register в чате
[бот регистрируется/логинится]  → сервер подтверждает
```

4. Проверьте чат: `bot TestBot_1 say Hello from SoulFire`
5. **POV-доказательство:** `export-basic-render 1280 720` — увидите, что «видел» бот.

Если на этом шаге что-то не сработало — **не увеличивайте количество**, чините сначала одного.

### Шаг 7. Масштабирование

| Ступень | Что ждём | На что смотреть |
|---|---|---|
| 1 бот | вход + капча + регистрация | все шаги из Шага 6 |
| 5 ботов | то же, параллельно | время решения капчи, лимиты LLM, ошибки регистрации |
| 10 ботов | стабильность | MSPT/TPS сервера, дисконнекты, очередь AI-запросов |
| 20+ ботов | деградация | MSPT > 40 мс — повод остановиться и разбираться |

Уникальные ники обязательны на всех ступенях, иначе боты будут кикать друг друга.

## Тот же тест через CLI (когда захотите автоматизировать)

```bash
java -jar SoulFireCLI.jar \
  --bot-address 127.0.0.1:25566 \
  --bot-join-delay-min 2000 --bot-join-delay-max 4000 \
  --account-file accounts.txt --account-type OFFLINE \
  --auto-register-enabled true \
  --auto-register-password-format 'TestPass123' \
  --auto-register-register-command '/register %password% %password%' \
  --auto-register-login-command '/login %password%' \
  --captcha-solver-enabled true \
  --captcha-solver-image-source MAP_IN_HAND \
  --captcha-solver-captcha-trigger CHAT_MESSAGE \
  --captcha-solver-text-trigger '/captcha' \
  --captcha-solver-captcha-regex '/captcha (\w+)' \
  --captcha-solver-model llava \
  --ai-api-base-url http://localhost:11434/v1 \
  --ai-api-key '' \
  --start
```

`accounts.txt` для offline — по одному нику на строку:
```
TestBot_1
TestBot_2
TestBot_3
```

Полезно отключить на этапе чистого теста входа: `--auto-reconnect-enabled false`.
Полный список флагов: `java -jar SoulFireCLI.jar --generate-flags`.

## Что НЕ делать на первом прогоне

- ❌ Не запускать 50 ботов «сразу посмотреть» — вы получите «оно упало» вместо данных.
- ❌ Не подключать прокси, пока не работает вход без них.
- ❌ Не включать kill-aura / auto-chat / anti-afk до того, как отлажен просто вход.
- ❌ Не отключать капчу на тестовом сервере «чтобы заработало» — тогда вы не проверите требование №1.
  Если нужно прогнать массовую нагрузку — делайте это **отдельным окном** и давайте bypass только
  машине-генератору (EpicGuard `/guard whitelist add`, permission `mapcha.bypass`, ipset и т.п.).
- ❌ Не использовать в `auto-register` реальный пароль от важного аккаунта.
- ❌ Не забывать про лимиты AI-провайдера: 20 ботов × капча = 20 запросов к модели почти одновременно.

## Диагностика: что чаще всего идёт не так

| Симптом | Причина | Что делать |
|---|---|---|
| Бот не подключается вовсе | версия протокола не та, сервер в online-mode, а аккаунт offline, вайтлист/бан, сервер на `127.0.0.1` недоступен из backend | сверить версию, проверить причину в `disconnect-logger`, попробовать вручную обычным клиентом |
| Таймаут подключения | неверный адрес/порт, SRV, файрвол | проверить адрес из машины backend, `--bot-connect-timeout` |
| Капча не решается | карта **не в главной руке** (для `MAP_IN_HAND`), нечитаемый POV, текстовая модель вместо vision, неверный Response Command, нет доступа к API | `inventory current` + `export-map` → посмотреть картинку; поднять POV-разрешение; сменить модель на vision; проверить логи backend |
| Капча приходит, но бот молчит | regex/триггер не совпал с реальным сообщением сервера | скопировать точную фразу из `chat-logger` и подправить trigger/regex |
| Регистрация не проходит | в чате нет `/register`/`/login`, другой синтаксис, нужен другой алиас, задержка слишком мала | уточнить команду на сервере, проверить руками от своего клиента, поправить шаблон и delay |
| Боты кикают друг друга | дубликаты ников | уникальные имена, проверить список аккаунтов |
| Сервер «держит» меньше ботов, чем ожидалось | `connection-throttle`, `max-players`, анти-бот, rate-limit | `connection-throttle: 0`, поднять `max-players`, проверить конфиг защиты |
| MSPT растёт необъяснимо | генерация чанков, плагин, дефолтный render distance | `/spark profiler start` на 2 минуты, предгенерация Chunky |

### Ошибка запуска приложения: «Timed out while waiting for the base Minecraft instance to initialize block models»

Полный текст ошибки в логе:

```
[main/INFO]: Using graphics backend OpenGL, using drivers:
[main/INFO]: Using graphics device:  ()
[main/ERROR]: Couldn't compile program for pipeline minecraft:pipeline/gui: ... (returned program ID 0)
[main/ERROR]: Couldn't compile program for pipeline minecraft:pipeline/gui_textured: ...
Fatal error during SoulFire launch:
java.lang.IllegalStateException: Timed out while waiting for the base Minecraft instance to initialize block models
```

**Причина:** графический бэкенд. Приложение SoulFireClient 2.10.1 скачивает «подходящий» серверный JAR
той же версии — **2.10.1** (в логе видно `managed-mod-2.10.1.jar` и `Loading Minecraft 26.2`).
В 2.10.1 ещё нет нового headless-Vulkan-рендерера: клиент стартует с OpenGL-бэкендом, шейдеры не
компилируются (`program ID 0`), и через 30 секунд ожидания инициализация блок-моделей отваливается
по таймауту.

Исправления вошли в **2.10.2** (02.10.2026) и позже:
`feat(renderer)!: replace CPU rasterizer with headless Vulkan`,
`feat(renderer): bundle a portable headless Vulkan runtime`,
`fix(launcher): explicitly select the Vulkan graphics backend` (лаунчер теперь передаёт
`--graphicsBackend VULKAN`). Плюс 2.10.2 несёт с собой lavapipe (Vulkan на CPU), поэтому GPU,
драйверы и дисплей не нужны.

**Решение: запустить GUI-клиент с сервером 2.10.2.** На экране «Подключение к серверу SoulFire»:

1. Скачать серверный JAR нужной версии:
   https://github.com/soulfiremc-com/SoulFire/releases/download/2.10.2/SoulFireDedicated-2.10.2.jar
2. В блоке **Server jar** переключить с **Official** на **Custom** и выбрать этот файл
   (в настройках Custom-сборки хранится путь + SHA-256; версия Official определяется файлом
   `soulfire-server-version.txt` внутри приложения, поэтому сам «Official» останется 2.10.1).
3. **Запуск.** Приложение один раз скачает клиент Minecraft 26.3 и Vulkan-рантайм — это нормально.

**Что должно быть в логе после фикса:** `--graphicsBackend VULKAN` в аргументах, ни одного
`Couldn't compile program for pipeline`, и вместо фатального таймаута — старт сервера SoulFire.
Если всё равно видите `Using graphics backend OpenGL` — выбран старый JAR, вернитесь к шагу 1–2.

**Если Custom не помог:** запустите серверную часть отдельно —
`java -jar SoulFireDedicated-2.10.2.jar` и подключите GUI к ней по адресу + токену
(раздел документации «Run a SoulFire server»). JVM-аргументы и объём памяти `-Xmx` к этой ошибке
отношения не имеют — их менять не нужно.

### Как «запустить .jar» (и нужно ли это вообще)

**Для исправления ошибки с рендером запускать JAR вручную не нужно.** Десктопное приложение само
запускает серверную часть: сначала скачивает `SoulFireDedicated-<версия>.jar` с GitHub, проверяет
SHA-256 и стартует его своей встроенной Java 25. Ваша задача — только подсунуть ему нужный файл:
**Server jar → Custom → выбрать скачанный `SoulFireDedicated-2.10.2.jar`**. Всё остальное — как раньше.

Вот что лаунчер делает под капотом (для понимания):

```
<встроенная java.exe> [JVM-аргументы из поля выше] -Dsf.grpc.port=<порт> -jar SoulFireDedicated-x.y.z.jar
```
рабочий каталог = папка данных; путь к Java и JAR показаны в окне «Диагностика процессов».

#### Если всё-таки хотите запустить JAR руками (свой терминал / отдельная машина)

1. **Найдите встроенную Java 25** (обычная системная Java для этого JAR не подойдёт — нужна 25+):

```powershell
Get-ChildItem "$env:APPDATA\soulfire\local-data\jvm-25" -Recurse -Filter java.exe |
  Select-Object -First 1 -ExpandProperty FullName
```

2. **Создайте отдельную папку** под данные (у сервера там лежат инстансы, аккаунты, `secret-key.bin`,
   скачанный Minecraft) и перейдите в неё — именно она будет рабочим каталогом.

3. **Запустите:**

```powershell
cd C:\soulfire-server
& "C:\Users\admin\AppData\Roaming\soulfire\local-data\jvm-25\...\bin\java.exe" `
  -Xmx8G -Dsf.grpc.port=38765 -jar C:\путь\SoulFireDedicated-2.10.2.jar
```

Первый старт скачивает библиотеки и клиент Minecraft 26.3 — это нормально и займёт время.
Остановка — `Ctrl+C` в терминале или команда `stop`.

4. **Подключить GUI к этому серверу:** в консоли сервера выполните `generate-token api` — получите JWT.
   В приложении выберите подключение к внешнему серверу и укажите адрес (`http://127.0.0.1:38765`)
   и этот токен.

⚠️ Не запускайте вручную тот же JAR на **той же папке данных**, что и встроенный сервер приложения —
они подерутся за файлы. И если Java старее 25, JAR не стартует (`UnsupportedClassVersionError`).

## Прокси: подключить и настроить

**Нужны ли они вообще?** На своём сервере — обычно нет: лишняя прослойка только добавляет латентность и
искажает измерения. Прокси нужны, когда сервер/анти-бот режет по IP, либо когда не хочется светить свой
домашний IP.

### Импорт в GUI (по шагам, как в версии 2.10.x)

1. Экземпляр → **Настройки прокси**.
2. Кнопка **«+ Добавить прокси»** → в выпадающем меню выбрать **тип**:
   **HTTP / SOCKS4 / SOCKS5 / URI**. Тип выбирается **до** импорта — от него зависит разбор строк.
   *Обычную запись `ip:port` импортируйте как SOCKS5, а списки со схемами (`socks5://…`) — как URI.*
3. Откроется окно **«Импортировать SOCKS5 прокси»** с тремя вкладками:
   | Вкладка | Что делать |
   |---|---|
   | **Из буфера обмена** | просто нажать — возьмёт текст из буфера |
   | **Из файла** | выбрать свой `.txt` (одна строка = один прокси) |
   | **Из URL-адреса** | вставить **ссылку на список** (напр. `https://raw.githubusercontent.com/monosans/proxy-list/main/proxies/socks5.txt`) — сервер SoulFire сам скачает её и импортирует ответ. ❗Это не поле для одного прокси: строку `socks5://…@ip:port` тут поймает тост «Не удалось загрузить данные» |
   | поле «Вставьте текст сюда…» | вставить строки руками → кнопка **«Загрузить из текста»** |
4. После импорта: тост «Импортировано N прокси!» и вопрос **«Проверить импортированные прокси?»**
   → **«Проверить прокси»**.
5. В окне «Проверить прокси» задать: **адрес проверки** (по умолчанию `mc.hypixel.net` — заменить на
   свой сервер, напр. `swarkfound.gomc.fun`), число одновременных проверок, таймаут → **«Начать проверку»**.
   Нерабочие прокси SoulFire **удаляет сам**.
6. Настройки страницы: **Bots per proxy** `5–10`, **Shuffle proxies** ON, **Sticky proxies** ON.
   Сохраняются автоматически.

**Про колонку «Адрес»:** префикс `inet://` — это нормально, так SoulFire хранит адрес внутри
(`inet://1.2.3.4:1080` = TCP-адрес и порт; `unix://` бывает только у unix-сокетов). Импорт разобрал
строки правильно, если после `inet://` стоит `ip:port`.

**Пример: один платный прокси от proxy6** (карточка даёт `URL = socks5://ЛОГИН:ПАРОЛЬ@IP:ПОРТ`).
Подходят три записи — выберите любой вариант импорта:

```
# тип URI (сам разберёт протокол, логин и пароль):
socks5://cA4nLE:7ZAfJk@45.11.125.130:9273

# тип SOCKS5 (стандартная запись ip:port:логин:пароль):
45.11.125.130:9273:cA4nLE:7ZAfJk

# тип SOCKS5 (альтернативная запись логин:пароль@ip:port):
cA4nLE:7ZAfJk@45.11.125.130:9273
```

Если в логине/пароле есть `@`, `:` или `/` — берите вариант **URI** и подставьте их
percent-encoding'ом (`@` → `%40`, `:` → `%3A`, `/` → `%2F`), иначе строка разберётся неверно.

Для **Shared**-прокси (значок `Shrd`, до 3 клиентов у провайдера) ставьте **Bots per proxy 3–5**,
а не 10: с одного IP в анти-боте не должно светиться слишком много аккаунтов.
Прокси применяется к **новым** подключениям — после добавления перезапустите ботов (`bots stop` → `bots start`).

Полезно: кнопка **«Получить прокси»** — это просто ссылка на soulfiremc.com/get-proxies (рекомендованные
платные сервисы), списки она не импортирует. Выделенные строки в таблице дают панель действий
(удалить / экспортировать / проверить выбранные). Готовые списки из `free-proxies/`
(и результат `scripts/proxy-parser.py` → `socks5-working.txt`) импортируются как **SOCKS5**.

#### Если проверка пишет «не удалось» у ВСЕХ прокси

Это **нормальный** результат для бесплатных списков, но проверьте по порядку:

1. **Адрес проверки с портом.** Если сервер на нестандартном порту (панель хостинга это показывает),
   в поле адреса нужно `swarkfound.gomc.fun:ПОРТ`, а не только домен.
2. **Проверьте на заведомо живом сервере:** поставьте адрес проверки `mc.hypixel.net` и нажмите проверку.
   * Тоже всё «не удалось» → прокси мёртвые либо **закрывают порт 25565** (большинство бесплатных
     прокси пускают только 80/443 — для Minecraft они бесполезны).
   * Прошло с Hypixel, но не с вашим → режет ваш сервер (анти-бот/DDoS-защита хоста видит датацентр-IP).
3. **Проверьте разбор строк:** колонка «Адрес» должна быть `1.2.3.4:1080`. Если там
   `socks5://1.2.3.4:1080` — импорт разобрался неправильно: удалите всё и импортируйте заново как
   SOCKS5 (без схемы) либо как URI (со схемой).
4. **Проверка одного прокси вручную** (PowerShell, есть в Windows 10+):
   ```powershell
   curl.exe -x socks5h://IP:PORT -m 10 https://api.ipify.org
   ```
   Печатает IP → прокси жив, но, возможно, блокирует 25565. Таймаут/ошибка → прокси мёртв.
5. **Диагностика парсером** (показывает, где обрыв):
   ```powershell
   py scripts\proxy-parser.py --input free-proxies\socks5-RU.txt --no-fetch --threads 50
   ```
   Статусы: `dead` — прокси мёртв, `bad-socks` — не SOCKS5/нужна авторизация, `tunnel` — туннель есть,
   но сервер не ответил (значит, дело в сервере/анти-боте), `mc` — всё работает.

**Вывод:** если мёртвые или блокируют 25565 — берите 2–4 платных IPv4 (~30–120 ₽/шт в месяц) и заранее
уточните у поддержки, что SOCKS5 пускает на **произвольные порты** (не только 80/443).

#### Проверка прокси бывает ложной (важно)

Встроенная проверка шлёт **status-пинг** на адрес из поля проверки и **всегда удаляет** неответившие.
Ложное «не удалось» бывает, если: в адресе нет порта (сервер не на 25565), либо хостинг/анти-бот режет
server-list пинги, но спокойно пускает игровые подключения. Реальный критерий для платных прокси —
**подключился ли бот** (бот → detail → лог; серверный лог видит IP прокси). Хотите прогнать чекер —
ставьте нейтральный адрес (`mc.hypixel.net`): он проверяет живость прокси, а не доступность вашего сервера.

#### `ProxyConnectException` в логе — как читать

`Disconnected with message: Internal Exception: io.netty.handler.proxy.ProxyConnectException:
socks5, password, /IP:ПОРТ => ДОМЕН/ip:25565, status: ...`

| Хвост сообщения | Что значит |
|---|---|
| `socks5, password` | прокси ответил и **авторизация прошла** — прокси живой |
| `CONNECTION_REFUSED(5)` | **цель отказала** подключению с этого IP (защита/анти-бот сервера либо хостинга) |
| `timeout` | прокси не смог достучаться до цели за своё время |
| `Host unreachable / Network unreachable` | до цели нет маршрута с IP прокси |

Диагноз ставится сравнением: тот же прокси против **другого** MC-сервера (напр. `mc.hypixel.net:25565`).
Ответил там и отказал у вас → режет ваш сервер; отказал везде → провайдер прокси блокирует 25565.
`scripts/proxy-parser.py` теперь пишет эти причины в выводе и в `socks5-report.csv`.

```
ip:port                                # без авторизации
ip:port:user:password                  # логин+пароль
user:password@ip:port                  # альтернативная запись

socks5://ip:port
socks5://user:password@ip:port
socks4://user@ip:port                  # SOCKS4 без паролей
http://user:password@ip:port
```

Смешанный список — только через URI-записи в одном файле.

### Настройки, которые реально влияют

| Настройка | По умолчанию | Что делать вам |
|---|---|---|
| **Bots per proxy** | `-1` (без лимита, распределяет равномерно) | Поставьте осмысленный лимит (например, `5–10`) — так вы не выжжете прокси и увидите, как работает очередь |
| **Shuffle proxies** | `false` | **Включить** |
| **Sticky proxies** | `false` | **Включить**, чтобы бот при реконнекте возвращался на тот же прокси (иначе его IP «прыгает») |
| **Proxy check address** | `mc.hypixel.net` | ❗**Обязательно заменить на адрес своего сервера** — иначе вы проверяете, что прокси ходит на Hypixel, а не на вашу цель |
| **Proxy check concurrency** | `10` | Оставить; для десятков прокси можно поднять |
| **Proxy check timeout** | `30` с | Поднять до 60, если прокси медленные/далёкие |
| **Use proxies for account auth** | `false` | Включать только для Microsoft-аккаунтов: игровой трафик и трафик авторизации идут **разными маршрутами**, отсюда частая ошибка «прокси рабочие, а логин падает» |

### CLI-эквивалент

```bash
--proxy-file proxies.txt --proxy-type SOCKS5 \
--proxy-bots-per-proxy 10 --proxy-shuffle-proxies true --proxy-sticky-proxies true \
--proxy-proxy-check-address swarkfound.gomc.fun \
--account-use-proxies-for-account-auth false
```

### Порядок проверки (не пропускать)

1. Один бот **напрямую** — базовая линия.
2. Импортировать **один** прокси и проверить его.
3. Тот же бот **через прокси** — сверить в логах Minecraft-сервера, что source IP сменился.
4. Только потом — весь список и остальные боты.

**Нюансы перед оплатой:** у proxy6 закрыт только 25-й порт (значит, 25565 должен работать), у belurk
стоит уточнить у поддержки; shared-IP делят до 3 человек — возможны чужие баны. Если «много рабочих
прокси за 100 ₽» обещает какой-то сервис — это почти всегда IPv6 или мёртвый список.

**Не забывайте:** 100 ₽ хватает не потому, что прокси дешёвые, а потому что ботов надо 5–10 на один IP.
Если сервер режет датацентр-подсети целиком — не поможет никакой бюджет: тогда whitelist/bypass
на своём же сервере.

⚠️ Дешёвые датацентр-IP анти-бот вашего сервера может резать сразу — это нормально. Тогда либо
whitelist на своём же сервере, либо мобильные/резидентские (дорого), либо 1–2 бота без прокси.

### Бесплатные прокси: где брать и как проверить

Публичные прокси бесплатны, но: живут минуты-часы, используются сотнями людей, среди них есть
«медовые ловушки» (пишут трафик). **Никогда** не вводите через них пароли и не подключайте
Microsoft-аккаунты — только offline-боты и тесты. Анти-бот чужого/своего сервера такие IP видит
насквозь: один адрес = десятки «игроков».

Готовые снимки списков лежат в `free-proxies/` (см. `free-proxies/README.md`):
`socks5-RU.txt` (51 РФ-адрес), `socks5-fresh-150.txt`, `socks5-big-1500.txt` — формат `ip:port`,
импортируются в SoulFire как есть.

Живые источники (обновляются каждые 5–60 минут):

```
https://raw.githubusercontent.com/monosans/proxy-list/main/proxies.json          # + гео и ASN
https://raw.githubusercontent.com/TheSpeedX/PROXY-List/master/socks5.txt
https://raw.githubusercontent.com/hookzof/socks5_list/master/proxy.txt
https://raw.githubusercontent.com/proxifly/free-proxy-list/main/proxies/protocols/socks5/data.txt
https://raw.githubusercontent.com/roosterkid/openproxylist/main/SOCKS5_RAW.txt
```

Парсер `scripts/proxy-parser.py` (стандартный Python, зависимостей нет) сам собирает пул из
**21 источника** (GitHub-списки, публичные API, HTML-сайты), проверяет каждый прокси настоящим
SOCKS5-туннелем до вашего сервера с **реальным Minecraft status-пингом** и складывает рабочие
в один файл:

```bash
python scripts/proxy-parser.py --target swarkfound.gomc.fun:25565 --country RU --limit 300
```

Результат: `socks5-working.txt` — **готовый список для импорта в SoulFire** (ip:port, отсортирован
по задержке), плюс `socks5-working-auth.txt` (с логином/паролем), `socks5-tunnel-only.txt`,
`socks5-pool.txt` (весь пул) и `socks5-report.csv` (задержка, страна, источник, версия сервера).
Ключи: `--merge` (дописать к прошлым результатам), `--top N`, `--tcp-only`, `--shuffle`,
`--sources monosans,geonode`, `--threads`, `--timeout`, `--fetch-timeout`.
Лёгкая версия на 5 источников — `scripts/free-proxies.py`.

Второй вариант — импортировать список в SoulFire и прогнать встроенную проверку прокси
(**Настройки прокси → Proxy check address = адрес своего сервера**).

**Ожидания:** из публичных SOCKS5 рабочими оказываются единицы процентов, и почти все они уже
в чёрных списках анти-ботов. Для теста «работает ли прокси-режим в SoulFire» бесплатных хватает;
для флота из 10–20 ботов — берите 2–4 платных IP за 240–500 ₽/мес.

## Много ботов: как завести флот

### 1. Подготовка памяти

Каждый бот — полноценный клиент Minecraft. В поле JVM-аргументов приложения задайте `-Xmx`
(16 ГБ ОЗУ → `-Xmx8G`), оставив 2–4 ГБ системе. Если Minecraft-сервер крутится на том же ПК — вычтите его.

### 2. Аккаунты

**Настройки аккаунтов** → генерация offline-аккаунтов: количество, например, `20`, формат `TestBot_%d`
→ появятся `TestBot_1 … TestBot_20`. Ники **обязаны быть уникальными** (дубликат = кик предыдущего бота).
Для online-mode — импорт Microsoft-аккаунтов.

### 3. Плавный вход

| Настройка | Для флота |
|---|---|
| Min/Max Join Delay | `3000–6000` мс (чем больше ботов, тем шире разброс) |
| Concurrent Connects | `1–3` — одновременно подключающихся ботов |
| `auto-reconnect` | Держать **выключенным** во время чистого теста входа |

`Concurrent connects` — главный параметр: резкий залп входов упирается в `connection-throttle`,
лимиты анти-бота и лимит слотов сервера, и вы тестируете не сервер, а защиту.

### 4. Запуск ступенями (не всё сразу)

| Ступень | Как запускать | Что смотреть |
|---|---|---|
| 1 | Один бот через Overview → **Запуск** | капча, регистрация, чат |
| 5 | «Запустить всех» / `bots start` | время входа, ошибки логина, MSPT |
| 10 | То же | TPS/MSPT, причины киков |
| 20+ | То же | деградация; MSPT > 40 мс — стоп |

Команды в **Терминале**:

```
bots start          # запустить всех настроенных ботов экземпляра
online              # сколько РЕАЛЬНО подключено (запрошено ≠ подключено)
bots stop           # остановить всех
bot TestBot_7 stop-task
```

«Запрошено» и «подключено» — разные вещи: часть ботов может висеть в очереди на прокси или
переподключаться, поэтому всегда сверяйтесь с `online` и списком игроков на сервере.

### 5. Проверьте сервер перед флотом

- `max-players` — не меньше планируемого числа ботов;
- `connection-throttle: 0` (Bukkit-сервера режут входы: 1 подключение / 4000 мс);
- анти-бот/капча: либо выключены на **тестовом** инстансе, либо машина-генератор в вайтлисте
  (EpicGuard `/guard whitelist add`, permission `mapcha.bypass`, ipset и т.п.);

### ⚠️ Ограничение арендованного хостинга

Если сервер живёт на хостинге (в вашем случае домен `*.gomc.fun` выдаёт hosting-minecraft.pro),
массовый вход чужих ботов — это, во-первых, почти наверняка против правил хостинга, во-вторых,
упрётся в их DDoS-защиту и `max-players` тарифа. Для настоящего стресс-теста поднимите копию сервера
**локально или на своём VPS**: там вы контролируете и лимиты, и защиту, и правила. На арендованном
сервере ограничьтесь проверкой механики (1–5 ботов: вход, капча, регистрация, чат).

## Готовый скрипт: авто-вход, авто-регистрация, авто-капча

В репозитории два готовых файла для импорта в SoulFireClient (**Scripts → значок загрузки → выбрать файл**):

| Файл | Когда нужен |
|---|---|
| `soulfire-scripts/auto-login-captcha.soulfire-script.json` | Сервер принимает **просто код** в чат (самый частый случай) |
| `soulfire-scripts/auto-login-captcha-command.soulfire-script.json` | Сервер требует **команду** `/captcha <код>` |

### Что делает скрипт

```
On Join  → Wait 1.5s (+jitter до 4s) → Print "вошёл: <ник>"

On Chat  → содержит /reg(ister)?   → RateLimit → Wait 0.7s → Send Chat "/register ПАРОЛЬ ПАРОЛЬ"
On Chat  → содержит /log(in)?      → RateLimit → Wait 0.7s → Send Chat "/login ПАРОЛЬ"
On Chat  → совпало captcha/капч/код→ RateLimit → Wait 0.4s → Print код → Send Chat "<код>"
```

Почему так:
- **Wait + jitter** — ответы не уходят мгновенно одинаково у всех ботов, выглядит человечнее и не ловит рейт-лимиты;
- **Rate Limit** — защита от циклов: если сервер повторяет приглашение, бот не заспамит его ответами
  (ключи `register-reply`, `login-reply`, `captcha-reply`, replenish ~1 токен в 20–50 с);
- **Regex с capture-группой** — код капчи выдёргивается из сообщения (`Регекс Замена` с `$1`), поэтому
  в чат уходит **только код**, а не вся строка сервера;
- **Print** — в логах скрипта видно, вошёл ли бот и какой код распознан (удобно отлаживать).

### Что обязательно поправить после импорта

1. Открыть узлы `reg_cmd` и `login_cmd` (константы строк) и заменить `CHANGE_ME` на свой тестовый пароль
   в обоих местах. Для варианта с командой — ещё проверить префикс `/captcha ` в узле `cap_prefix`.
2. Проверить регулярку капчи под формулировку **вашего** сервера: уведите в чате реальное сообщение
   (например, «Введите капчу: A1B2C3») и убедитесь, что паттерн ловит именно код.
   Текущий паттерн: `(?is)(?:captcha|капч|code|код)[^A-Za-z0-9]{0,24}([A-Za-z0-9]{3,10})`
3. Сохранить скрипт и **снять галочку «paused»** (импорт всегда приходит выключенным).
4. Запустить **одного** бота и посмотреть логи скрипта + чат.

### ⚠️ Не включайте одновременно скрипт и плагины

Если включён плагин `auto-register` **и** этот скрипт — бот отправит `/register` дважды.
То же с `captcha-solver` + скрипт. Выберите **одно**:

| Что нужно | Чем делать |
|---|---|
| Капча-картинка (карта в руке, POV) | **Только плагин `captcha-solver`** — скрипт не умеет читать изображения |
| Капча-текст в чате | Плагин (`TEXT_BASED`) **или** этот скрипт — но не оба |
| Регистрация/логин | Плагин `auto-register` **или** этот скрипт — но не оба |

## Максимальная оптимизация под флот

Порядок действий, если цель — «завести много ботов на минимуме ресурсов»:

**1. Память и JVM**

```
-Xmx8G -XX:+UseZGC          # при 16 ГБ ОЗУ; ZGC — меньше пауз на большом флоте
```
Оставляйте 2–4 ГБ системе. Если Minecraft-сервер на том же ПК — вычтите его.

**2. Снизить стоимость одного бота**

| Настройка | Значение | Эффект |
|---|---|---|
| Client settings → Render distance | `2` (по умолчанию уже 2) | меньше чанков качается и обрабатывается — главный рычаг экономии |
| Particle status | `MINIMAL` | меньше сетевого мусора |
| IO_URING (Linux) | включить | ниже CPU на сеть; на Windows недоступно |
| Ignore Packet Handling Errors | включить | бот не отваливается из-за одного пакета |

**3. Плавный вход**

| Настройка | Для флота |
|---|---|
| Min/Max Join Delay | `3000–7000` мс |
| Concurrent Connects | `1–2` |
| `auto-reconnect` | выключен на время чистого теста входа |
| Прокси | `Bots per proxy` 5–10, `Shuffle` + `Sticky` включены |

**3а. Когда нужен быстрый заход (стресс-режим, а не скрытность)**

| Настройка | Значение | Почему |
|---|---|---|
| Concurrent Connects | `5–10` | параллельные входы вместо очереди по одному |
| Min/Max Join Delay | `0–250` мс | убираем «человеческую» паузу |
| Auto-reconnect | **выключен** | иначе при отказах получается петля «вход → отказ → реконнект через 2 с», которая жрёт CPU и маскируется под медленный заход |
| Плагины | все лишние выключены | каждый включённый плагин = код на каждом боте |
| Запуск | волнами из Terminal: `bots stop` → `bots start` | предсказуемая ступень вместо «само рассосётся» |
| POV/стриминг | выключен | рендер самого дорогого стоит |

Помните: SoulFire заходит медленно, потому что каждый бот — настоящий Minecraft-клиент. Быстрый заход
на сотни ботов дают протокольные инструменты (BotMark, mc-bots, rust-mc-bot) — см.
`SOULFIRE-СТРЕСС-ТЕСТЕРЫ.md` → «Гибрид SoulFire + заливка».

**4. Отключить всё лишнее в плагинах**

Для массового входа держите включёнными только: `chat-logger`, `disconnect-logger`, `client-settings`,
`auto-register` **или** скрипт. Выключите до лучших времён: `kill-aura`, `auto-eat`, `auto-armor`,
`auto-totem`, `auto-chat-message`, `dialog-handler`, `ai-chat-bot`, `anti-afk` (последний — по необходимости).

**5. Заходить ступенями**

1 → 5 → 10 → 20 → 50, выдержка 5–10 минут на ступень. Смотреть: `online` (фактические подключения),
MSPT/TPS сервера, RAM генератора, причины киков в `disconnect-logger`. Стоп-условие задать заранее
(MSPT > 50 мс, пошли дисконнекты, RAM у предела).

**6. Не забыть про ограничения площадки**

На арендованном хостинге массовый вход ботов = нарушение правил + их DDoS-защита. Для настоящего
нагруза — своя копия сервера локально или на VPS.

## Чек-лист первого прогона

**До теста**
- [ ] Копия сервера + бэкап; Spark установлен; baseline MSPT зафиксирован
- [ ] `connection-throttle: 0`, `max-players` поднят, капча **включена**
- [ ] SoulFire установлен, Integrated server запущен, инстанс `Test1` создан
- [ ] Bot Settings: адрес, версия протокола, join delay 1–3 с, без прокси
- [ ] Аккаунты добавлены (offline-генерация или Microsoft), ники уникальны
- [ ] AI Settings заполнены; vision-модель выбрана (если капча картинкой)
- [ ] Plugins: `auto-register` включён, `captcha-solver` настроен под ваш тип капчи
- [ ] `auto-reconnect` выключен на время чистого теста входа

**Во время**
- [ ] 1 бот: вход → капча → регистрация → чат (`say`)
- [ ] Проверены `inventory current` и `export-map` (карта видна и читаема)
- [ ] `export-basic-render 1280 720` — POV-скриншот сохранён
- [ ] Ступени 5 → 10 → 20 с выдержкой; MSPT, дисконнекты, ошибки фиксируются
- [ ] «Запрошено ≠ подключено»: сверяем `online` с числом запущенных

**После**
- [ ] Боты остановлены явно; сервер вернулся к baseline; реконнекты прекратились
- [ ] Отчёт: MSPT/TPS по ступеням, время решения капчи, ошибки, POV-скриншоты, что чинить
- [ ] Тестовое окружение откатили из бэкапа
