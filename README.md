# SoulFire Fleet Console

Веб-панель для управления несколькими Minecraft Java-серверами через SoulFire. Это **контроллер**, а не новая реализация Minecraft-протокола: аккаунты, соединения и переподключения остаются на стороне SoulFire.

## Что уже сделано

- Каждый SoulFire-инстанс отображается как отдельная серверная группа — можно управлять ботами на разных целях независимо.
- Запуск и остановка выполняются фоновыми задачами; UI не ждёт, пока клиенты подключатся или отключатся.
- Команды запуска ограничены двумя одновременно обрабатываемыми группами. Для остановки выделена отдельная очередь до восьми групп — она не ждёт очередь запуска.
- Если нажать «Остановить» во время запуска, ожидающий старт отменяется, а уже отправленная команда приводится к последнему выбранному состоянию.
- На карточках есть сводка по подключённым, ожидающим, повторно подключающимся и ошибочным ботам; подробности доступны по каждой группе.
- Для подключённого бота доступен POV-поток (960 × 540, примерно 1 кадр/с) и ручные команды движения/поворота. Каждое движение — ограниченный по времени импульс с гарантированным сбросом клавиш.
- Новую группу можно создать с адресом сервера и offline-профилями. Существующие Microsoft-аккаунты импортируются штатными средствами SoulFire.
- API-токен держится только в памяти backend-процесса: он не сохраняется в `localStorage`, файле конфигурации или Git.

Команда запуска/остановки подтверждает **желаемое состояние** в SoulFire. Реальное подключение и отключение происходит в фоне и отображается в статусе группы. Интервалы входа и прочие параметры соединения остаются настройками SoulFire.

## Запуск для разработки

Требуются Node.js 22+ и запущенный SoulFire backend, доступный с машины, на которой работает backend этой панели.

```bash
npm install
npm run dev
```

Откройте `http://localhost:5173`. Backend панели слушает только loopback на порту `4173`; Vite проксирует `/api` на него. Для локального SoulFire укажите `http://127.0.0.1:38765`.

В консоли SoulFire создайте API-токен командой:

```text
generate-token api
```

Вставьте URL и токен на экране подключения. При удалённом подключении используйте HTTPS. Панель должна запускаться на хосте, который может достучаться до SoulFire API: `127.0.0.1` означает localhost **хоста панели**, а не браузера.

## Сборка и запуск

```bash
npm run build
npm start
```

Панель будет доступна на `http://127.0.0.1:4173`. Для запуска за reverse proxy задайте `HOST=0.0.0.0` и `PORT` по необходимости. Не публикуйте интерфейс в интернет без HTTPS и дополнительной аутентификации: доступ к панели даёт возможность управлять подключёнными ботами.

## Разные серверы

Создайте отдельный инстанс SoulFire для каждой цели. Панель показывает все инстансы, доступные API-токену. Кнопки запуска и остановки работают в пределах выбранного инстанса, а «Запустить всё» / «Остановить всё» отправляют команду нескольким группам.

При создании группы панель использует SoulFire provisioning API и добавляет до 100 offline-профилей за один запрос. Это требует совместимой версии SoulFire с возможностью named provisioning. Microsoft-аккаунты и прокси добавляйте в SoulFire; панель сможет управлять такими профилями после импорта.

POV и ручное управление используйте только на серверах, где у вас есть разрешение. Панель намеренно не автоматизирует рассылку в общий чат/личные сообщения, обход мутов или ротацию аккаунтов. При ограничении со стороны сервера оператор должен остановить бота и соблюдать правила площадки.

## Версии и ограничения

SDK закреплён на `@soulfiremc/sdk` 2.10.2. SoulFire проверяет совместимость SDK/API во время подключения и откажет, если версии несовместимы. При таком отказе используйте согласованные версии SDK и backend.

Панель предназначена для тестирования серверов, которыми вы владеете или на которые у вас есть разрешение. Она не заменяет лимиты и настройки нагрузки SoulFire.
