## 1. Что это такое

**SoulFire — продвинутый инструмент для запуска ботов в Minecraft.** Он поднимает полноценных
клиентов Minecraft **без игрового окна** (headless) и позволяет массово управлять ими: подключать
к серверам, ходить, копать, строить, сражаться, торговать, писать в чат.

Ключевой архитектурный момент версии 2.0+: **SoulFire запускает официальный клиентский код
Minecraft как особый Fabric-мод**. То есть боты — это не самописная реализация протокола
(как у Mineflayer), а реальный клиент с настоящей физикой, предсказанием движения, коллизиями и
сетевым поведением. Отсюда и следствие: **плагины SoulFire — это обычные Fabric-моды**.

⚠️ В README прямое предупреждение: использовать только на серверах, которыми вы владеете или на
тестирование которых у вас есть разрешение. Ответственность за нецелевое использование — на пользователе.

Репозиторий, который вы смотрите, содержит **CLI и серверную часть (dedicated server)**.
Официальный GUI-клиент лежит в отдельном репозитории: https://github.com/soulfiremc-com/SoulFireClient

## 3. Возможности

### Управление и инфраструктура
- GUI (несколько тем) и CLI; **инстансы** — границы прав и конфигурации, внутри них боты.
- Настройки на сессию: число ботов, задержка входа и т.п.; профили сохраняются и загружаются.
- Аккаунты: **Microsoft** (учётные данные и Device Code) и **offline**; поддержка **Java и Bedrock Edition**.
- Прокси: **HTTP, SOCKS4, SOCKS5**, импорт списков, «залипающее» распределение прокси по ботам.
- Консольные команды, WebDAV-доступ к файлам, JWT-токены для API, метрики, Spark-профайлер.
- Разделяемый сервер: один dedicated-сервер, к которому подключаются клиенты; Docker и Pterodactyl.

### Версии Minecraft
Нативный клиент — самая свежая версия (в документации указана **26.3**), поддержка более старых
версий реализована через встроенный **ViaFabricPlus** (ViaVersion + ViaLegacy + ViaBedrock).
Список огромный: от свежих снапшотов вплоть до **Classic, Alpha и Beta** и Bedrock
(в докладе перечислено ~95 версий/диапазонов, включая April Fools-версии вроде `3D Shareware`).
ViaVersion на стороне целевого сервера **не нужен** — трансляция пакетов идёт на стороне бота.

### Встроенные плагины (включаются/выключаются per instance)
`ai-chat-bot` (AI-собеседник в чате), `anti-afk`, `auto-armor`, `auto-chat-message`, `auto-eat`,
`auto-jump`, `auto-reconnect`, `auto-register` (AuthMe), `auto-respawn`, `auto-totem`,
`captcha-solver`, `chat-logger`, `client-brand`, `client-settings`, `dialog-handler`,
`disconnect-logger`, `fake-virtual-host`, `kill-aura`, `server-list-bypass` (обход анти-ботов
вроде EpicGuard, пингует список серверов перед подключением), `forwarding-bypass`
(обход прокси-форвардинга). По умолчанию `auto-armor`, `auto-eat`, `auto-totem` выключены.

### Задачи ботов (task providers, `mod/.../server/task/`)
GoTo, FollowEntity, CollectBlocks, Excavate, Build, Explore, Craft, Smelt, Brew, Farm, Fish, Sleep,
Breed, Guard, Flee, AttackEntity/AttackNearest/RangedAttack, ContainerTransfer, VillagerTrade,
MaintainLoadout, AutoEat/AutoArmor/AutoTotem/AutoRespawn + менеджер задач с приоритетами и
контролем ресурсов.

### Пути и взаимодействие
A* pathfinding: диагональные движения, паркур, копание и установка блоков; `move`, `follow`,
`mimic <entity>` (повторять движение другого игрока), `lookat`, прямое управление
`control forward/backward/left/right/jump/sneak/reset`, работа с инвентарём и сущностями,
`useitem`/`useitemon`, `click left|right`, `say`, `respawn`, `health`, `stop-task`.

### Рендер без окна
Сервер тащит с собой **headless-Vulkan-рантайм** (Vulkan loader + Mesa lavapipe для CPU-рендера,
MoltenVK для Metal) — системные Vulkan-пакеты и дисплей не нужны; при наличии драйвера GPU
работает аппаратное ускорение. OpenGL отключён. Команды `export-map`, `export-basic-render`,
`export-render-debug-dump` сохраняют изображения карт и **POV-картинку «глазами бота»**
(с настраиваемым разрешением и дистанцией прорисовки).

## 4. Способы автоматизации (от простого к сложному)

1. **Команды** — одна операция оператором (`move`, `collect`, `excavate`, `say`, `bot <names> ...`, `instance ...`, `repeat <n> ...`).
2. **Визуальные скрипты** — граф в GUI: триггеры (чат, таймеры, события) → данные → действия.
   Исполняет **сервер**, редактору не нужно оставаться открытым. Есть рецепты/примеры и отладка.
3. **Durable tasks** — длительные задачи, продолжающие работу после отключения вашей программы.
4. **Официальные SDK** — `@soulfiremc/sdk` (TypeScript; браузеры и JS-рантаймы с `fetch`) и
   `soulfire` (Python). Оба — типизированные **gRPC-Web** клиенты. Умеют: запуск/останов/рестарт
   ботов (по одному, по ID или счётчиком), поток статусов, чат, запросы к миру, взаимодействие,
   инвентарь, pathfinding, **эксклюзивные «лизы» контроля** над ботом для координации скриптов,
   композицию поведений (collect/follow/combat/eating/building), инстансы и ботов по имени,
   offline-аккаунты по умолчанию, установку аккаунтов и прокси, **автоматическую установку и
   управление локальным dedicated-сервером**. TS-пакет требует Effect 4, Python — effect-py.
   Плюс `@soulfiremc/beat-game` — планировщик автоматического прохождения Minecraft (одиночный бот
   или команда, с сохранением и продолжением прогресса), работает как внешний воркер.
5. **Плагины** — Fabric-моды с доступом к коду Minecraft и SoulFire, **миксинами**, событиями,
   страницами настроек, регистрацией RPC и прав. Шаблон: SoulFirePluginExample; зависимости из
   CodeMC Maven; точка входа `SoulFireAPI.registerServerExtension(...)`; jar кладётся в `minecraft/mods`.
   Часть сторонних Fabric-модов работает без изменений (но всё, что завязано на рендер/звук, — вряд ли).

## 5. Что можно делать на практике

**Тестирование серверов (основной официальный сценарий)**
- Базовая линия → постепенное наращивание нагрузки → поведенческие сценарии → фиксация результатов.
- Проверка: надёжность входа (login ramp), поведение лобби, чат/команды/переподключения,
  отзывчивость мира при генерации чанков, консистентность разных версий протокола, корректность
  маршрутизации через прокси, стресс-тест на большое число ботов.
- Стресс-тест без нагрузки на ваш ПК: dedicated-сервер на отдельной машине + прокси-пул.
- Визуальные доказательства багов: POV-скриншоты, экспорт карт, логи чата/дисконнектов.

**Автоматизация и боты**
- Регистрация на AuthMe-серверах, решение капчи, авто-респавн, анти-AFK, авто-еда/тотем/броня,
  kill-aura, авто-реконнект, массовые рассылки в чат по расписанию.
- Фермы и добыча ресурсов: collect/excavate/farm/fish/breed/smelt/brew/craft/build, торговля с
  жителями, снаряжение команды.
- Координация флотов через SDK с лизами на управление, сценарные скрипты в GUI.
- AI-чат-бот для игроков (плагин `ai-chat-bot`) — можно сделать «живого» NPC-собеседника.
- Исследование: beat-game runner для авто-прохождения прогрессии игры.

**Разработка**
- Свои плагины (Fabric + миксины) и свои команды/события/RPC/права.
- Свои приложения на TS/Python поверх gRPC-Web, при необходимости — сгенерированный низкоуровневый клиент.
- Встраивание в панели: Docker-образ, шаблон Pterodactyl, dedicated-сервер с WebDAV.

**Чего делать не стоит / на что смотреть**
- Запуск на чужих серверах без разрешения — нарушение README/лицензии и правил площадок.
- AGPL-3.0: если вы используете SoulFire в сетевом сервисе, исходники этого сервиса придётся открыть.
- Обратная сторона «реального клиента»: это тяжёлая JVM-нагрузка, нужен Java 25+ для сборки, а
  каждый бот — полноценный клиент. Для больших флотов требуется нормальное железо и прокси.
- Плагины = Fabric-моды с миксинами = произвольный код: ставить только доверенные.

## 7. Сводка

SoulFire — зрелый (4+ года активной разработки) open-source инструмент для **массового
управления настоящими клиентами Minecraft без графики**. Его сильные стороны: реальный клиентский
код Fabric вместо эмуляции протокола, поддержка почти всех версий Minecraft и Bedrock через
ViaFabricPlus, headless-рендер POV, полноценный API (gRPC + типизированные SDK + визуальные скрипты
+ Fabric-плагины) и готовая инфраструктура для распределённого запуска (dedicated, Docker, панели).
Основное применение по замыслу авторов — нагрузочное тестирование и автоматизация серверов,
которыми вы владеете, плюс разработка ботовой логики.
