# Лучшие стресс-тестеры Minecraft-серверов (обзор и рецепты)

Данные проверены по GitHub API и README проектов на **04.10.2026**.

> Раздел «стресс-тестеры» — это про нагрузку на **свой** сервер. Инструменты ниже применяйте только
> на серверах, которыми владеете или на тестирование которых есть письменное разрешение: по сути они
> генерируют L7-нагрузку, и на чужом сервере это трактуется как атака (об этом прямо пишут в README
> rust-mc-bot и dodoflix/minecraft-stress-tester).

---

## 0. Сначала главное: это три РАЗНЫХ класса инструментов

Их постоянно путают, и из-за этого получают неверные выводы.

| Класс | Что делает | Что измеряет | Кого брать |
|---|---|---|---|
| **A. Flood / connection-level** | Быстро открывает N соединений, бот часто вообще «мёртвый» (не отвечает на пакеты) | Предел входа: login-хендшейк, аллокации, throttling, анти-бот, потолок слотов | rust-mc-bot, BotMark, mc-bots `-x`, stress-bot (1.8), go-bots |
| **B. Behavior / «живые» боты** | Ходят, прыгают, грузят чанки, копают, пишут в чат, торгуют | Влияние реального геймплея: чанки, физика, ИИ, плагины, БД | **SoulFire**, PureGero/minecraft-stress-test, mc-bots, Holy Client, LambdaAttack, Mineflayer/NWP-скрипты |
| **C. Серверные фейк-игроки** | Боты создаются **внутри** сервера (плагин/мод) | Нагрузку на игровой цикл без сети и авторизации | **Carpet `/player`** (Fabric), **BetterStressbots** (Paper) |

Важно: класс A даёт цифру «сколько соединений держит», но **не** отвечает на вопрос «что будет, когда
50 игроков начнут играть». Класс B отвечает, но дороже по железу. Класс C — самый удобный для «своего»
сервера, потому что обходит капчу, online-mode, анти-бот и не требует прокси вообще.

## 2. Подробно по инструментам

### 2.1. mc-bots — «швейцарский нож» ⭐ 540, Java, MIT, последнее обновление 08.2025

- Версия ботов: **1.21.7** (сервер 1.21.8); для старых версий — релизы в репозитории.
- Требуется **Java 17+**.
- Фичи: SOCKS4/SOCKS5 (файл или URL), задержка входа, сообщения/команды на входе, «реалистичные» ники
  или список из файла, онлайн-аккаунты Microsoft (`-o`), эмуляция гравитации (`-g`), авто-респавн,
  два режима экономии (`-m`, `-x`), управление ботами из консоли (`.list`, `.control`, `.exit`).

```bash
# 1 бот (проверка)
java -jar mc-bots-1.2.17.jar -s 192.168.0.10:25565

# 30 ботов с задержкой 4-5 с, реалистичные ники с префиксом
java -jar mc-bots-1.2.17.jar -s 192.168.0.10:25565 -c 30 -d 4000 5000 -p BOT_ -r

# Много ботов в минимальном режиме (для потолка по соединениям)
java -jar mc-bots-1.2.17.jar -s 192.168.0.10:25565 -c 200 -x -d 2000 3000

# Прокси (SOCKS5) + команды на входе
java -jar mc-bots-1.2.17.jar -s play.example.com -t SOCKS5 -l proxies.txt -c 50 -j "/register pass123 && /login pass123"
```

**Плюсы:** реально много ботов на одном ПК, прокси, гибкие опции, живое управление.
**Минусы:** версия одна и не самая свежая; «умного» поведения нет (ходьба/копание — нет, только гравитация);
обновляется нечасто.

### 2.2. rust-mc-bot — максимум ботов на минимуме ресурсов ⭐ 61, Rust, GPL-3.0, обновлён 04.2026

- Создан для теста Minestom: «все существующие реализации ботов падали раньше сервера».
- Версии: тег **1.21.8** актуальный; в тегах — 1.21.0, 1.20.6, 1.20.4, 1.20.1, 1.19.x, 1.18.1.
- **Онлайн-режим не поддерживается** (осознанно, ради производительности и во избежание злоупотреблений).
- Сборка из исходников: `cargo build --release`.

```bash
./rust-mc-bot 127.0.0.1:25565 1000        # 1000 ботов
./rust-mc-bot 127.0.0.1:25565 1000 8      # 1000 ботов, 8 потоков
```

**Плюсы:** лучший выбор, чтобы найти предел входа; честно предупреждает про юридику.
**Минусы:** боты «тупые» (только подключение), нет прокси, нет GUI, нужен Rust.

### 2.3. BotMark — готовый Rust-бинарник ⭐ 77, MIT, обновлён 08.2026

От команды **Pumpkin** (альтернативная реализация сервера). Есть готовые сборки под Linux/macOS/Win.

```bash
./botmark --ip 127.0.0.1:25565 --count 50 --delay 100
# тонкая настройка поведения:
./botmark --ip 127.0.0.1:25565 -c 100 -d 100 \
  --enable_movement true --enable_jumping true --enable_physics true \
  --enable_rotation true --enable_swing true \
  --enable_spam_message true --spam_message "test" --spam_message_delay_min 100 --spam_message_delay_max 250
```

Флаги: `-c/--count`, `-d/--delay`, `-t/--timeout`, спам-сообщения и их частота, вращение головы,
взмахи руками, случайное движение, прыжки, симуляция физики (гравитация/трение/инерция/knockback).
Требует `online-mode=false`.

**Плюсы:** ничего собирать не надо, приятный набор поведенческих переключателей.
**Минусы:** версия MC в README явно не указана (уточняйте по релизам/исходникам), нет прокси,
нет метрик.

### 2.4. dodoflix/minecraft-stress-tester (`mcst`) — единственный «про метрики» ⭐ 9 (очень новый), TS/Node ≥24, MIT, обновлён 10.2026

- Заявлено: оценка TPS, **воронка подключений**, latency, throughput, причины киков; масштабирование
  до тысяч ботов по процессам; web-GUI; REST control-plane; программируемые «blueprints» ботов.
- Отказывается запускаться без флага `--i-am-authorized` (подтверждение, что сервер ваш).

```bash
npx minecraft-stress-tester --host 127.0.0.1 --count 100 --i-am-authorized
docker run --rm -p 8080:8080 ghcr.io/dodoflix/minecraft-stress-tester gui --host 0.0.0.0   # web-GUI
mcst scan        # защитное сканирование своего сервера
mcst debug       # консоль одного бота
```

**Плюсы:** наконец-то показывает *эффект* нагрузки, а не только «сколько сокетов открылось»; GUI/API.
**Минусы:** совсем свежий (9★, мало отзывов) — используйте как дополнительный слой метрик, а не как
единственную опору.

### 2.5. PureGero/minecraft-stress-test — загрузка чанков и мира ⭐ 154, Java, обновлён 08.2026 (26.2)

- Боты заходят в offline-режиме, **летают и исследуют мир** → лучший способ проверить генерацию чанков
  и entity-tracking, а не только вход.
- Нужны `online-mode=false` и `allow-flight=true`; ботам рекомендуется creative (не умеют респавниться).
- Управление на ходу из консоли: `count 1000`, `speed 0.2`, `radius 600`.

```bash
java -Dbot.count=100 -Dbot.ip=127.0.0.1 -Dbot.port=25565 \
     -Dbot.login.delay.ms=100 -Dbot.radius=1000 \
     -jar target/minecraft-stress-test-1.0.0-SNAPSHOT-jar-with-dependencies.jar
```

**Плюсы:** современная версия (26.2), чанки/мир, управление в реальном времени.
**Минусы:** сборка через Maven; ботам нужен creative/полёт; нет прокси.

### 2.6. LambdaAttack — старый, но с GUI ⭐ 295, Java, MIT, обновлялся до 07.2024

- GUI **и** CLI, настраиваемое количество и задержка, формат/список имён, лог ошибок,
  **SOCKS-прокси**, автоматическая регистрация на «cracked» серверах (`/register` + `/login`
  с паролем `LambdaAttack`), аккуратный дисконнект в конце.
- Версии: MC 1.11+ (по умолчанию в CLI указан 1.15.2), Java 9+.

```bash
java -jar lambdaattack.jar -h 127.0.0.1 -p 25565 -c 100 -d 500 -n "Bot-%d" -r
```

**Плюсы:** GUI, прокси, авто-регистрация — удобно для быстрых прогонов.
**Минусы:** фактически не обновляется с 2024 г., зависимость от старой MCProtocolLib, свежие версии MC
под вопросом.

### 2.7. Minecraft-Holy-Client — C#-платформа ⭐ 178, Apache-2.0, обновлён 09.2025

Готовые десктоп-сборки (linux-x64/arm64, osx-arm64) в релизах, но **это превью-версии**
(`2.0.0-preview...` от 2024). Хороший вариант, если ваш стек — .NET.

### 2.8. sim0n/stress-bot — только 1.8 ⭐ 58, Java, 2022

Заявлено 5–6% CPU на **500 ботов** (Ryzen 9 5950X). Требует `online-mode=false`; рекомендует
выставить `connection-throttle: 0` в `bukkit.yml`, иначе Bukkit режет входы (1 за 4000 мс).

### 2.9. Экзотика

- **go-bots** (Go): YAML-конфиг, register/login, спам чата, «умные» кулдауны, прыжки/взмахи/повороты,
  кастомный packet-spam (README честно пишет «не тестировано, лучше не использовать»),
  низкое потребление RAM/CPU.
- **minecraft-bot-flood** (PHP): открывает соединения максимально быстро и **не отвечает** на пакеты —
  грубый «флуд входа»; версия протокола задаётся вручную.
- **Minecraft-Holy-Client, ХЛВ-подобные** и десятки свежих репозиториев на 0–10★ — почти всегда форки/
  обёртки; проверяйте код перед запуском.

## 3. Отдельно: серверные фейк-игроки — лучший вариант для вашего сервера

Если цель — протестировать **свой** сервер, а на нём капча, онлайн-режим, анти-бот или прокси-слой,
внешние боты требуют обходов (SoulFireBypass, прокси, отключение капчи). **Внутренние боты всего этого
не требуют вообще** — они появляются уже «внутри» сервера как настоящие `ServerPlayer`.

### 3.1. BetterStressbots (Paper-плагин)

Боты — реальные `ServerPlayer`: грузят чанки, считаются в списке игроков, стреляют событиями
`PlayerJoinEvent`/`PlayerQuitEvent`/`PlayerCommandPreprocessEvent`, ходят или летают.
Поддержка **1.21.x** и **26.x**, жёсткий предел 1000 ботов (защита от OOM). Требует `allow-flight=true`.

```
/stress count 100      # задать количество (ещё не спавнит)
/stress mode fly       # fly или walk
/stress radius 500     # радиус блуждания
/stress speed 0.15     # скорость, блоков/тик
/start                 # заспавнить
/stress chat /rtp      # все боты выполняют команду как обычные игроки
/botcmd /spawn         # шорткат для команд
/stress stop           # убрать ботов
/stress status
```

**Почему это лучший старт для теста своих плагинов:** проверяются права, команды, экономика, регион-плагины
(через `/rtp`), тик-нагрузка — без прокси и без обхода защиты.

### 3.2. Carpet (Fabric) — `/player`

Классика для Fabric-серверов и техических миров: `/player <ник> spawn` создаёт фейк-игрока,
который ведёт себя как настоящий (грузят чанки, спавнят мобов, тикают рандомы), умеет ходить, копать,
ставить блоки. Плюс инструменты измерения: `/log tps`, `/tick health`, `/tick freeze`, `/tick warp`,
`/player <ник> <действие> randomly` (случайные интервалы), `rejoin` (сохранение позиции).

```mcfunction
/player Bot1 spawn
/player Bot1 attack continuous
/player Bot1 use perTick 4
/tick warp 6000          # «промотать» 5 минут игры для проверки деградации
/carpet commandPlayerActionPerTick true
```

**Плюсы:** бесплатно, встроено в стандартный техический тулкит, даёт мгновенный ответ «а сервер вообще
переживёт N игроков».
**Минусы:** только Fabric-сервер; фейк-игроки не проходят реальную сеть/авторизацию (это и плюс, и минус).

## 4. Методика: как правильно прогнать (чтобы цифры что-то значили)

### 4.1. Подготовка сервера (тестовый инстанс!)

```properties
online-mode=false        # для внешних оффлайн-ботов; для серверных плагинов не нужно
allow-flight=true        # если боты летают (BotMark, minecraft-stress-test, BetterStressbots)
max-players=200          # временно поднять — иначе упрётесь в лимит раньше железа
white-list=false
enforce-secure-profile=false
```
```yaml
# bukkit.yml / spigot.yml
connection-throttle: 0   # иначе Bukkit режет входы: 1 подключение / 4000 мс
```
- **Отключите на тестовом инстансе** капчу, анти-бот (EpicGuard/Sonar/LimboFilter), rate-limit по IP,
  автобан за флуд — иначе вы тестируете защиту, а не сервер (для этого — отдельный прогон).
- Сделайте бэкап мира и конфигов.
- Поставьте **Spark** (`/spark profiler`, `/spark tps`) и следите за MSPT.

### 4.2. Ступени нагрузки

1. **Baseline** — 0 ботов, 10 минут: MSPT/TPS, CPU, RAM, сеть, фоновые задачи.
2. **1 бот** — убедиться, что вход, спавн, чанки, команды работают.
3. **5 → 10 → 20 → 50 → 100 …** — на каждой ступени держите одинаковое окно наблюдения (например, 5 минут).
4. **Стоп-условие** — задайте заранее: MSPT > 50 (TPS < 20), рост дисконнектов, ошибки в логе,
   исчерпание RAM у сервера **или у машины с бот-инструментом**.
5. **Восстановление** — остановить ботов явно и наблюдать падение метрик столько же, сколько длилась ступень.

### 4.3. Что фиксировать

| Метрика | Где смотреть |
|---|---|
| MSPT / TPS | `/spark tps`, `/log tps` (Carpet), табло сервера |
| CPU / RAM сервера | `htop`, панель хостинга, `/spark profiler` |
| CPU / RAM машины с ботами | там же — **это тоже узкое место** (особенно у Java-инструментов) |
| Время до рабочего состояния | от подключения до возможности идти/копать |
| Ошибки входа | консоль сервера + лог инструмента |
| Причины киков | лог сервера; у `mcst` — сводка |
| Генерация чанков | рост RAM, размер мира, MSPT при `radius`-полётах |
| Сеть | трафик на бота (КБ/с), число TCP-соединений |

### 4.4. Правила, без которых тест врёт

- **«Запрошено ≠ подключено»**: если бот-инструмент сам упёрся в CPU/RAM, вы измеряете его, а не сервер.
  Следите за его потреблением.
- **Flood ≠ геймплей**: 500 мёртвых сокетов не покажут, что будет от 50 игроков с фермами, сундуками и
  плагинами регионов.
- **Меняйте одну переменную за прогон**: число ботов, задержка входа, поведение, версия, настройка сервера.
- **Повторяйте ступень**, если нужен ответ «всплеск или деградация».
- **Синхронизируйте часы** сервера и машины ботов.
- **Не смешивайте** нагрузочный тест и тест защиты (капча/анти-бот) в одном прогоне.

## 5. Что взять под ваш конкретный случай

У вас свой сервер, есть капча, вероятно онлайн/полу-онлайн режим, есть желание проверять свой сервер.

**Рекомендуемый набор — три инструмента, три разных вопроса:**

1. **Серверные боты — BetterStressbots (Paper) или Carpet `/player` (Fabric)**
   Вопрос: «Переживёт ли игровой цикл, плагины и команды N игроков?» Ни прокси, ни капча, ни online-mode
   не мешают. Быстро, бесплатно, встроено.
2. **mc-bots (или rust-mc-bot, если нужен максимум) — внешний слой**
   Вопрос: «Сколько реальных сетевых входов выдерживает сервер и как ведёт себя анти-бот/прокси-слой?»
   mc-bots — если нужны прокси и команды на входе; rust-mc-bot/BotMark — если нужен потолок по соединениям.
3. **SoulFire — поведенческий слой**
   Вопрос: «Что будет, когда боты реально *играют*: ходят по новым чанкам, копают, торгуют, пишут в чат
   и капча решается так, как её увидит игрок?» Плюс POV-скриншоты и логи как доказательства.

Опционально:
- **dodoflix/mcst** — если нужны чистые метрики (TPS/latency/kick-reasons) и web-GUI, но помните, что
  проект очень новый.
- **PureGero/minecraft-stress-test** — если основная боль — генерация чанков (боты летают и исследуют мир).

### 5.1. Почему SoulFire заходит медленно и почему у него нет стресс-режима

- **1 бот SoulFire = полноценный Minecraft-клиент**: он реально грузит мир, парсит чанки, держит рендер.
  Отсюда 3–15 с на вход и CPU-предел в десятки ботов на ПК. Это цена за то, что он **проходит
  капчу-картинку** и играет как человек (POV, движение, чат, плагины).
- **Стресс-режима нет by design**: «залить 1000 соединений» — противоположная задача, для неё есть
  протокольные инструменты (ниже).
- **Важный нюанс из логов**: при обрывах авто-реконнект превращается в петлю
  «вход → отказ → реконнект через 2 с» — она и выглядит как «медленный заход», и жрёт CPU.
  На стресс-прогоне `auto-reconnect` выключать, ботов перезапускать пачкой (`bots stop` → `bots start`).

### 5.2. Гибрид «SoulFire + заливка» — рекомендованный стек

| Слой | Инструмент | Сколько ботов | Роль в тесте |
|---|---|---|---|
| Поведенческий | **SoulFire** | 1–10 | проходит капчу, регистрацию, живёт в лобби, даёт POV и логи |
| Заливка | **BotMark** (готовый exe) или **mc-bots** | 100–2000 | потолок входов; движение/прыжки/чат-спам у BotMark, прокси и команды на входе у mc-bots |
| Серверный предел | **BetterStressbots** / Carpet `/player` | сотни | игровой цикл и плагины без сети, без капчи, без online-mode |
| Метрики | **mcst** | — | TPS, воронка подключений, latency, причины киков |

Порядок прогона (по очереди, каждый раз фиксируя MSPT/TPS):

1. **BetterStressbots**: 50 → 100 → 200 — понять предел самого игрового цикла.
2. **SoulFire**: 5–10 ботов с капчей — убедиться, что сценарий «вход → регистрация → лобби» работает.
3. **BotMark/mc-bots**: 100 → 300 → 600 — потолок сети, анти-бота и прокси-слоя.
4. Совмещать все три сразу не нужно: получите шум вместо цифр.

### 5.5. Разбор: GaetanOff/StressTest-MC (node + mineflayer + YAML)

Код прочитан целиком (source-анализ, не только README). Что внутри:

| Параметр | Факт из исходников |
|---|---|
| Стек | mineflayer ^4.26 + **mineflayer-pathfinder** + `socks`, ESM, GPL-3.0, зависимости ставятся npm/pnpm |
| Вход ботов | настоящий спавн (протокол клиента), `auth: offline` по умолчанию, имя `Bot_<поток>_<n>` |
| Движение | **реальный pathfinder** (`GoalBlock`), режимы `slow/normal/fast` (sneak/sprint) |
| Действия | `move`, `chat` (список сообщений + интервал), `interact` (right_click = activateBlock, left_click = dig), `command` |
| Мультипоточность | worker_threads: ботов делят на `threads` потоков (`botsPerThread = ceil(N/threads)`) |
| Прокси | SOCKS5 со списка, **с логином/паролем**, перебор до `maxRetries`, при неудаче — прямое подключение (⚠️) |
| Задержка входа | `botJoinDelay`, по умолчанию 500 мс (в README пишут 500, в конфиге 500) |
| Авто-реконнект | есть в `botLifecycle` (при обрыве), если не остановлено вручную |
| **Капча** | **нет вообще** — ни карты, ни текста (`messagestr`/`map` не обрабатываются) |
| **Авто-регистрация** | **нет** — но лечится штатно через `event.onJoin.execute` |

**Нагружает ли сервер?** Да, и заметно лучше «флуд-ботов»: боты реально спавнятся, ходят
(pathfinder → постоянные пакеты позиций, загрузка чанков и физики), пишут в чат, ломают/используют
блоки. Но: у ботов **нет капчи**, поэтому на вашем сервере они упрутся в неё и сядут в лимбо — нагрузка
будет только на «предбанник». Pathfinder также дорог по CPU на **вашей** стороне: на одном ПК
ориентируйтесь на ~50–200 ботов (не тысячи).

**Как использовать:**

```bash
git clone https://github.com/GaetanOff/StressTest-MC && cd StressTest-MC
npm install

# 1) config/config.json — задержка входа, потоки, прокси
#    botJoinDelay: 400, threads: 4, proxy.enabled: true + список {host, port, username, password}

# 2) config/scenarios/scenario-1.yml — цель и сценарий
#    numberOfBots: 100
#    server: { host: "play.cequar.ru", port: 25565 }
#    event.onJoin.execute: "/register pass12345 pass12345"   # регистрация
#    actions: move / chat / interact / command

node src/index.js scenario-1.yml     # лог: logs/bot.log, остановка Ctrl+C
```

Регистрация делается так: `event.onJoin.execute: "/register пароль пароль"` (и `wait: 3s` перед
действиями, чтобы сервер успел ответить). Капчу этот инструмент не решает — её либо отключают
на тестовом инстансе, либо проходят отдельно (`scripts/captcha-test-bot.js`), а StressTest-MC
используют как «стену входов» уже после капчи/лимитов по IP.

**Вывод:** хороший готовый инструмент для «входа + движения + чата» и удобен YAML-сценариями, но
три пункта из вашего требования он не закрывает: капча, авто-регистрация по сообщению сервера,
и слепой откат на прямое подключение при сбое прокси. Для связки «капча + регистрация + нагрузка»
в репозитории есть `scripts/stress-bots.js` (капча: OCR/ручной режим, регистрация по шаблонам,
движение, прокси на каждого бота, статистика).

### 5.6. Про NeoProxy, BareApi, BebraProxy и подобное

Это не «клиенты для теста», а **серые/чёрные бот-платформы под ключ** (платно, из закрытых чатов,
часто с криптооплатой). Использовать их против своего сервера бессмысленно и опасно:
вы получаете чужой бинарник с неясным содержимым, без исходников, без гарантий, а на арендованном
хостинге — прямое нарушение правил. Всё, что они делают, на своём сервере воспроизводится открытыми
инструментами за вечер (см. `stress-bots.js`).
